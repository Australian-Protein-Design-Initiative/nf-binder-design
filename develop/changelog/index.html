Changelog

All notable changes to this project will be documented in this file.

The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

[Unreleased]

Added

  • --method rfd4_proteina: binder design with RFD4-Proteina. The model co-designs sequence and structure, so there is no inverse-folding step between generation and scoring. An RFD4-Proteina condition spec (--rfd4_config, YAML or JSON) is the default interface and gives access to the full conditioning vocabulary; --input_pdb with --contigs and --hotspot_res generates one using the upstream default recipe for protein binders. Designs are split across tasks by --rfd4_designs_per_task, each with its own seed. Supports structural filters (--rfd4_filters), Boltz-2 refold scoring (--full_refold_with boltz), FoldSeek search (--do_foldseek), partial diffusion and inverse folding. Runs in the rfd4-proteina:0.0.3-aaccdd2_nv-cuda13 container, which is published for both amd64 and arm64 (...-arm64). On an arm64 host, add -c conf/platforms/arm64.config so the other steps use arm64 images too.
  • --full_refold_with takes a list of engines: refold scoring is one path now, whichever predictor does the folding. Each design's binder sequence is folded against its target with every engine named - af2, af2_mono, boltz, rf3, protenix, af3, openfold3, chai1, esmfold2, esmfold2_fast - and every engine gives the same columns in combined_scores.tsv, prefixed with its name: confidence (<tool>_iptm_max, <tool>_ipsae_max, <tool>_plddt_max, ...), RMSD against the design (<tool>_target_aligned_binder_rmsd_all, <tool>_complex_rmsd_all), the binder folded on its own (<tool>_monomer_vs_design_rmsd_all, <tool>_monomer_vs_complex_rmsd_all) and BindCraft interface metrics (<tool>_interface_dG, ...). A cross-engine consensus_z ranks designs when more than one engine is named. New parameters: --refold_metrics, --refold_structure_stat, --refold_binder_monomer, --refold_monomer_single_sequence, --refold_interface_scoring. The new REFOLD subworkflow takes designs as tuple(meta, structure) and holds nothing design-method-specific, so the other design workflows can adopt it unchanged. Wired into --method rfd4_proteina so far.
  • --method fold: multi-method structure folding for monomer and multimer/complex FASTA inputs with AF2, af2_mono (AF2 monomer weights on a chain-broken complex), Boltz-2, RosettaFold3, Protenix, AlphaFold3, OpenFold3, Chai-1, ESMFold2 and ESMFold2-Fast (esmfold2_fast). Shared MSAs (jackhmmer/HHblits or ColabFold, taxonomy-paired per engine for multimers), optional MSA subsampling, a per-structure score table (ipTM, pLDDT, ipSAE, pDockQ, LIS, ...) and EnGens clustering. AlphaFold3 weights are not bundled: download them under DeepMind's terms with models/download_af3_weights.sh, or point --af3_model_dir at them. ESMFold2 weights ship in its containers; esmfold2_fast always folds from sequence alone, and --esmfold2_single_sequence runs the full model MSA-free too. Also engens.nf for clustering an existing .cif/.pdb folder or glob.
  • --method fold_pulldown: target × binder pulldown across the same engines, with per-structure scores, an aggregate summary (within-tool z-scores and a cross-engine consensus_z) and a Quarto report. MSA cost is O(targets + binders) rather than O(targets × binders), and input ids are validated up front. Defaults to 5 structures per complex per engine (--n_predictions), with AF2 keeping all five models from its single run (--af2_keep_models all).
  • --templates for --method fold / fold_pulldown: known structures (.pdb/.cif, single chains or whole complexes) are matched to the chains being folded by sequence alignment, with no mapping file, and passed as per-chain templates to every engine except ESMFold2. Match cutoffs are --template_min_identity, --template_min_coverage, --template_min_aligned and --template_max_per_chain. fold_pulldown templates the target only unless --binder_templates, and by default holds Boltz's templated chains near their template (--boltz_template_force, 1.0 Å).
  • --boltz_refold_batch_size: fold several designs per Boltz refold task to amortise Boltz's per-invocation startup cost (default 1).
  • AlphaFold3 can be run the way Germinal runs it, so an AF3 refold of Germinal designs is comparable to the scores that run produced. --af3_paired_msa false emits "pairedMsa": "" for every chain (no cross-chain pairing); --af3_templates search omits the templates key so AF3's own data pipeline searches pdb_seqres/mmcif_files for templates on every chain, which --af3_run_data_pipeline true and --af3_db_dir (the ~630 GB AF3 database set) enable. --af3_seeds also takes a comma list, putting every seed in one job's modelSeeds; the seed list is then the replication, so the --n_predictions fan-out is suppressed and a run produces n_seeds × --af3_batch_size structures per complex. -profile af3_germinal_parity packages the whole combination with Germinal's target-only MSA mode and 5×5 sampling. Defaults are unchanged — without these AF3 still runs inference-only with a paired MSA and no templates.
  • conf/platforms/arm64.config: run on arm64 / aarch64 workstations (eg NVIDIA DGX Spark GB10) by pointing the amd64-only images at their arm64 builds - nf-binder-design-utils:0.1.7-arm64, boltz:v2.2.1-2_nv-cuda13-arm64, foldseek:10-941cd33-arm64, esmfold2:3.4.1.post1_nv-cuda13-arm64_{fast,full}_weights, rc-foundry:0.2.0_arm64-weights (RF3), bindcraft:nv-cuda13-arm64 and protenix:2026-09-21_85767b8_nv-cuda13-arm64_weights. Covers the RFD4-Proteina design path and its scoring, with boltz, esmfold2, esmfold2_fast, rf3 and protenix available as refold engines; AF2, AF3, OpenFold3 and Chai-1 have no arm64 image yet. Two of those images need a GB10-specific build rather than only an architecture swap. RF3 uses the -ngc2606 tag rather than the plain 0.2.0_arm64-weights one: the latter is built on CUDA 12.8, whose nvrtc cannot target sm_121, so on a GB10 it fails with nvrtc: error: invalid value for --gpu-architecture (-arch) when PyTorch's jiterator compiles erfinv. Protenix compiles its fused layer-norm extension at image build time for sm_70 to sm_100 only, so inference died at the first layer-norm call with no kernel image is available for execution on the device; the arm64 image adds sm_120 and sm_121 and rebuilds it. Protenix also needs HOME set to a writable path when run as the host uid under Docker, which the config does, since it caches under $HOME/.cache and an unset HOME resolves to /. Use it alongside a runtime config, eg -c conf/platforms/arm64.config -c nextflow.docker.config. It also sets --gpu_devices all and --gpu_slots_per_device 1: without --gpu_devices the GPU lock never engages and fold tasks run concurrently on the one device, which on a GB10 - where the 128 GB is shared between host and GPU - is enough to run it out of memory.
  • refold/refold_sample_scores.tsv: one row per refolded sample, keyed by id, tool, batch and model, carrying that sample's own confidence, RMSD and interface scores with nothing reduced. combined_scores.tsv is one row per design, so every number in it is already a statistic over the samples; this table keeps the values those statistics were computed from, so min, max, mean, median or standard deviation over the samples can be worked out afterwards.
  • --refold_structure_stat (default selected): how several samples per design reduce to one value in the RMSD and interface columns of combined_scores.tsv. They now come from a single sample, the one the confidence ranking picks as best (by --consensus_metric, ipSAE), rather than a statistic per metric. The structural metrics all describe one set of coordinates, so taking the lowest RMSD and the lowest interface_dG independently gives a row that no predicted structure matches; and the interface metrics have no shared direction to take a best in anyway - interface_dG is better lower, interface_dSASA and interface_sc better higher. <tool>_selected_batch and <tool>_selected_model record which sample each design's structural columns came from - both, because an engine handed a list of seeds returns every sample from one batch. min|mean|max|first still apply one statistic to every structural column.
  • --fold_seed_list (default true): run --n_predictions as one invocation carrying every seed, for the engines that take a seed list and keep each seed's outputs apart. The alternative, one process per seed, loads the model that many times, and on a small complex the load is most of the wall time - ESMFold2-Fast measured 1m 8s per task on a GB10 for a two-chain complex, nearly all of it startup. Applies to esmfold2, esmfold2_fast (bin/fold/run_esmfold2.py now loops fold() over --seed with the model resident), openfold3 (its runner YAML's experiment_settings.seeds is already a list) and protenix (runner/inference.py loops for seed in seeds:). AF3 has the same ability under its own parameter, where a comma list in --af3_seeds already means "these seeds, one job". Boltz and RF3 are excluded because they are single-seed per process: Boltz calls seed_everything(seed) once, and RF3's inference engine config has seed: as a scalar. Set --fold_seed_list false to go back to one process per seed.
  • GPU provenance trace. Every GPU task now records the device it ran on to <outdir>/logs/gpu_trace_<datestamp>.txt: timestamp, task hash, process, hostname, n_gpus, and the GPU index, UUID, model, driver version and total memory. New parameters: --gpu_trace_dir, --gpu_trace_file.

Changed

  • Refold scoring is no longer Boltz-specific. BOLTZ_COMPARE_COMPLEX folded the complex and measured it against the design inside one process, which tied the metrics to one engine; folding, comparison and interface scoring are now separate steps that work from structures, so any engine's predictions go through the same scoring. --refold_oracles, which existed because the Boltz path could not take another engine, is deprecated and folded into --full_refold_with. Removed with it: --full_refold_create_target_msa, --full_refold_use_msa_server, --full_refold_alignment, --full_refold_target_fasta and --full_refold_target_templates - the refold takes its MSA and template choices from the fold stack (--create_target_msa, --use_msa_server, --msa_method, --templates), and a run that sets one of the old names stops with the replacement named. Column names change for --method rfd4_proteina: boltz_complex_plddt becomes boltz_plddt_max, while the RMSD columns keep their names. boltz_complex_pair_pae_min has no replacement: the engine-independent metric in its place is <tool>_pae_mean, the mean of the full PAE matrix, and the Boltz confidence JSON carries no PAE of any kind, so boltz_pae_mean is currently blank while the other engines populate it. Boltz does write the full matrix (pae_*.npz, already used for ipSAE), so filling the column is a matter of passing it to the parser. The refolded structures move from <outdir>/boltz_refold/ to <outdir>/rfd4_proteina/refold/.
  • The refold in --method rfd4_proteina now runs 5 structures per design per engine rather than 1, as 5 fold jobs of one sample each with seeds 42, 43, ... rather than one job of 5 samples. The engines that batch samples share a single trunk and recycling pass across them, so five samples from one seed differ only in the diffusion noise while five seeds re-run the whole prediction; the disadvantage is five model loads rather than one, roughly 45 s of fixed cost each for Boltz on a GB10. The split comes from per-engine batch sizes of 1, declared as --full_refold_<engine>_batch_size for the engines whose plain name nextflow.config already declares (boltz, esmfold2, chai1, openfold3, af3, and rf3 as before) and as --protenix_batch_size for Protenix, which this workflow declares itself. Setting one higher gives that engine a mixture: --n_predictions 6 --full_refold_boltz_batch_size 3 is 2 seeds x 3 samples. --method fold and --method fold_pulldown are unchanged. The refold's long tables and the interface-score PDB names gain the fold batch (<design>__<tool>__b<batch>.pdb), because every job writes its single sample under the same model index and the batch is what tells two seeds' samples apart.
  • RF3's engine flags are --full_refold_rf3_* in --method rfd4_proteina (ckpt_path, num_steps, n_recycles, batch_size, early_stopping_plddt_threshold, seed). The plain --rf3_* names belong to the design-time RF3 step in --method rfd3, where --rf3_batch_size means MPNN designs per RF3 task rather than samples per fold job, and a workflow's parameters are one flat namespace. Where a workflow declares the prefixed names the fold stack reads only those (lib/FoldParams.groovy), so a design-time value cannot leak into the refold. --method fold and --method fold_pulldown, which have no design-time RF3 step, keep the plain names.
  • --protenix_seeds takes a comma list again. It was a hard error because Protenix separates its seeds by directory (<name>/seed_<N>/predictions/) and not in the file name, so several seeds in one job collided in the flat fold/predictions/ gather and mis-paired their confidence files. PROTENIX_FOLD now reads the seed back out of the path and puts it into the names it publishes and scores (FoldNaming.protenixSeedBit), which is what makes a seed list usable.
  • Every structure predictor in --method fold / fold_pulldown (af2, af3, boltz, esmfold2, openfold3, protenix, rf3) now honours task.ext.args, so extra engine CLI arguments can be set from config without a pipeline parameter for each option. ALPHAFOLD2 was the only one that did not.
  • ColabFold MSAs are published as {sequence_id}.a3m (e.g. PDL1.a3m) rather than {fasta_stem}.N.a3m under a result/ folder.

Removed

  • --method boltz_pulldown, superseded by --method fold_pulldown: the same target × binder fan-out, MSA options and reporting, plus the other engines, per-chain template matching, multiple samples per pair and a cross-engine summary. --method fold_pulldown --methods boltz is the equivalent run, with structures written as mmCIF rather than PDB, --templates matched per chain rather than handed to Boltz wholesale, and the score table at fold_pulldown/fold_pulldown_scores.tsv.
  • bin/find_available_gpu.py and the --gpu_allocation_detect_process_regex / --germinal_gpu_allocation_detect_process_regex parameters. The script's GPU-busy detection never worked inside Apptainer containers - Set --gpu_devices to enable the lock-based allocator instead.

Fixed

  • Two fold runs in one workflow wrote their per-engine score tables to the same path, so the second overwrote the first and the merge downstream saw rows for complexes it never folded. The fold stack now takes a publish label (FOLD, FOLD_PREDICT and each engine subworkflow), which the refold uses to keep the complex folds and the binder-monomer folds apart.
  • bin/rmsd4all.py compared multi-chain structures in file order rather than in the order the --superimpose-chains / --score-chains lists gave, and rmsd_all pairs atoms by position. Two complexes holding the same chains but written in the opposite order - an RFD4-Proteina design, which writes the binder first, against a refold that writes the target first - had the binder measured against the target: 21 Å where the structures agree to 1.3 Å. The chains are now taken in the order asked for, which is what makes the two lists a statement of correspondence.
  • BindCraft interface scoring of a Boltz-refolded complex was given the design's binder chain id, but the refolded complex has its own chain ids (binder A, target B). Wherever the design's binder was not chain A - --method rfd4_proteina, where it is B - every interface metric, and the sequence column beside them, described the target rather than the binder.
  • rfd4_proteina: --rfd4_target_chain / --rfd4_binder_chain resolved to the literal string "false" when left unset, because the params default to boolean false and false.toString() is a non-empty, therefore truthy, string. The A/B default and the derivation from --contigs never ran, so filter metrics were computed on a chain that does not exist - every rg blank and every design rejected - and the binder sequence was read from the wrong chain.
  • rfd4_proteina: the boltz_monomer_vs_complex_rmsd_* columns in combined_scores.tsv were always empty. The merge stripped _model_0.pdb / _monomer from the RMSD table's structure1, but the values there end in _complex.pdb, so the key never matched a design id.
  • --boltz_num_workers (default: task.cpus, unchanged): Boltz's dataloader workers deadlock on some platforms, leaving the run at 0% GPU indefinitely rather than failing. conf/platforms/arm64.config sets it to 0. Previously --num_workers was hardcoded to task.cpus in three modules and could not be overridden, since a duplicate flag in ext.args does not win.
  • rfd4_proteina: COMBINE_RFD4_SCORES failed with Not a valid path value type whenever the filters rejected every design, because the empty-channel fallback passed Channel.of(file(...)) to ifEmpty, which takes a value rather than a channel.
  • RF3 wrote its caches to $HOME, which is / when the container runs as a uid with no passwd entry - what conf/platforms/arm64.config asks for under Docker so a task can write its own work directory. rf3 fold died with PermissionError: [Errno 13] Permission denied: '/.cache' before any folding. RF3_FOLD and ROSETTAFOLD3 now set XDG_CACHE_HOME, XDG_CONFIG_HOME and TRITON_CACHE_DIR inside the task directory, as the Boltz module already did.
  • rfd3: treat unset/false --rf3_batch_size as 1 (avoids Boolean→Integer cast failure when a shared config sentinel is present).
  • The GPU lock (--gpu_devices) failed whenever the tasks sharing it did not all run as the same user. Some images run as root and others are pinned to the invoking user (conf/platforms/arm64.config does this under Docker), and the lock files take the ownership of whichever task created them, so a task running as anyone else could not open one for writing and waited out --gpu_lock_timeout before failing. bin/gpu_lock.sh now creates the lock directory and its files world-writable, and a lock file it cannot write is reported once and fails the task immediately rather than being waited on. The GPU trace directory is created the same way; a trace row written by a task running as another user was previously dropped in silence. A lock directory left behind by an earlier run has to be deleted for the new permissions to take effect.
  • examples/pdl1-rfd/run-m3-full.sh and examples/pdl1-bindcraft/run-m3.sh: point at repo main.nf, pin NXF_VER=24.10.0, and drop mid-command # comments that broke the Nextflow invocation.
  • Root nextflow.config report/trace timestamps use params.trace_timestamp instead of a top-level def, so Nextflow >=26 can parse the root config (site profiles such as m3.config still use def and need NXF_SYNTAX_PARSER=v1 or Nextflow <26).
  • Remove unused random_choice helper from conf/platforms/m3.config.
  • Quarto reports: set writable XDG_* / Jupyter runtime dirs so rendering works in Apptainer (was failing with Could create runtime directory for jupyter transport).
  • Local multi-GPU runs no longer stack tasks on one card while another sits idle (#14).
  • docs workflow: main, develop and tag pushes no longer race each other deploying to gh-pages. A release triggered all three at once and two failed with cannot lock ref 'refs/heads/gh-pages', so the versioned docs were never published. Runs are now serialised and a rejected push is retried.

[0.3.1] - 2026-09-09

Added

  • BindCraft: support for multiple input PDBs via directory or glob, with per-PDB trajectories and per-target reporting.
  • BindCraft report: Wilson 95% confidence intervals on accept rates (overall, per-target, and per binder-length range); length-stratified i_pTM boxplots and accept-rate plots.
  • Automatic datestamped Nextflow report/trace/timeline/dag under ${outdir}/logs/ (no DATESTAMP / -with-report / -with-trace needed in wrappers).

Changed

  • BindCraft batch directories and design names use <pdbName>_<batchIndex> (e.g. batches/PDL1_0/) instead of a bare integer batch index. BindCraft output CSVs include a Target column with the input structure filename.
  • BindCraft helper scripts moved to bin/bindcraft/ (create_bindcraft_settings.py, bindcraft_scoring.py, add_bindcraft_target_column.py).
  • M3 platform configs (m3, m3_bdi): shared SLURM option variables at the top of each file (account, exclude, GPU/CPU presets); all jobs now pass --exclude=m3t100.
  • BindCraft report headline accept rate collapses MPNN duplicates (unique trajectories with ≥1 accepted design ÷ total trajectories); rate including all accepted MPNN sequences is shown alongside.

Fixed

  • BindCraft report accept summary: trajectory outcomes (Relaxed / LowConfidence / Clashing) now sum to total trajectories; Accepted / Rejected MPNN designs are shown separately.
  • BindCraft: process now fails (non-zero exit) when bindcraft.py crashes; previously | tee bindcraft.log masked the Python exit code so Nextflow marked the task COMPLETED.
  • bin/ipsae.py: score RF3, native AF2 and Protenix predictions correctly. RF3 is now its own input format (scalar iptm, 0-indexed per-atom pLDDT) rather than an AF3 variant; list-wrapped AF2 pae_model_*.json and Protenix full-data JSON are accepted; and the structure format is detected from the real file extension, fixing KeyError: 'id' on rfd3/Boltz outputs whose .pdb filename embeds .cif.
  • rfd3 modules pull rc-foundry:0.2.0-weights as an ordinary container image instead of oras://. The image was rebuilt as a multi-layer OCI image, so an oras:// pull now fails with ORAS SIF image should have a single layer, found 20.

[0.3.0] - 2026-07-09

Added

  • New --method rfd3 workflow for RFDiffusion3-based binder design using RosettaCommons/foundry (RF3 batching, Boltz full-refold scoring, optional FoldSeek on refolded designs).
  • Germinal antibody/nanobody design workflow (--method germinal).
  • FoldSeek structural search (--do_foldseek) for the rfd, bindcraft, boltzgen, and rfd3 workflows. Searches designed binder chains against structural databases (default: CATH50) to identify known folds and annotate results with CATH hierarchy descriptions. Supports local or remote search, gzip output, and optional HTML reports.
  • Spartan HPC platform configs spartan-a100.config (gpu-a100-short) and spartan-l40s.config (gpu-l40s) for University of Melbourne Spartan.
  • conf/platforms/monash_containers.config: container URL overrides so the m3, m3_bdi M3/MASSIVE platform configs pull mirrored containers from a Monash local server instead of ghcr.io. Some containers (SILENT_FROM_PDBS, MMSEQS_COLABFOLDSEARCH, FoldSeek) are not yet mirrored and still pull from their original registries.
  • RFD workflow docs: table of built-in and bind-mounted HyperMPNN --pmpnn_weights checkpoints in the proteinmpnn_dl_binder_design container.
  • Agent skill at .agents/skills/nf-binder-design/ for AI-assisted pipeline setup and execution.
  • bin/complex_sasa.py: per-residue delta SASA for target chains when a binder is removed from a complex, with optional site sums, batch PDB input, and --min-change-percent column pruning.
  • nf-test tests/pipeline/compilation.nf.test: launches rfd, rfd_partial, and rfd3 in -preview mode to verify every workflow/module compiles; run per Nextflow version with NXF_VER=<version> nf-test ... to guard against version-specific DSL parser regressions.

Changed

  • Docs: note Nextflow version compatibility. On Nextflow 26.04+ (new strict parser default), set NXF_SYNTAX_PARSER=v1 to use the legacy parser.
  • Trimmed README.md, testing section moved to docs/docs/extra/development.md, general docs cleanup and corrections.
  • manifest.nextflowVersion now bounds the supported range to !>=23.04.0, <26.10 (hard failure outside this range).
  • Set nextflow.enable.configProcessNamesValidation = false to silence the "There's no process matching config selector" warnings printed on every run (only the selected --method workflow is included, so the withName: selectors for other methods' processes match nothing).

Fixed

  • germinal: --method germinal no longer crashes with a MissingPropertyException when --germinal_pdb_dir is omitted; the documented default (../pdbs relative to the config) is now inferred correctly (config_path is a Path, which has no .parentFile).
  • rfd3: legacy --pmpnn_temperature, --pmpnn_augment_eps and --pmpnn_omit_aas flags are now honoured instead of being silently overridden by the modern --mpnn_* defaults. The modern name still takes precedence when both are set; defaults are unchanged (temperature 0.1, structure noise 0, omit CX, sequences-per-structure 1).
  • Nextflow 24.04.3 compatibility: the rfd3 workflow and boltz_refold_core subworkflow no longer trigger the "Variable already defined in the process scope" DSL parser error on Nextflow 24.04.3 (a bug fixed in the 24.10 parser rewrite). Channel/path local variables use plain assignments instead of def in these workflow bodies.
  • foldseek: database names containing / (e.g. Alphafold/UniProt50, Alphafold/Swiss-Prot) now download and search correctly; the download step creates the nested output prefix directory and the local search resolves prefixes nested one level deep.
  • examples/*/nextflow.dual-gpu.config: fixed if (params.gpu_devices) { maxForks = ... } inside withName: blocks, which printed a WARN: Unknown directive 'params' on every dual-GPU example run and hard-errored (Unknown config attribute) if --gpu_devices was not passed. Replaced with a plain ternary assignment and a local params { gpu_devices = '' } redeclaration so the overlay file can resolve the param without depending on cross-file config evaluation order.
  • rfd: configurable RFDIFFUSION via rfd_command and rfd_model_directory_path (Pawsey config overrides in pawsey_setonix.config; GPU behaviour uses existing require_gpu and gpu_devices).
  • rfd3: RFDIFFUSION3 and ROSETTAFOLD3 now fail fast with a clear message when nvidia-smi is not installed (previously died with a cryptic command not found under set -e).
  • combine_scores.sh: updated to the current results/rfd/af2_initial_guess/{pdbs,scores} output layout (was still pointing at the pre-reorg results/af2_initial_guess/...).

[0.2.0] - 2026-05-06

Added

  • New nci_gadi.config configuration profile for NCI Gadi HPC cluster.
  • Initial nf-test test scaffold (nf-test.config, tests/) with a process test for UNIQUE_ID and RFDIFFUSION; documented in docs/docs/testing.md.
  • BoltzGen: support for list-valued entities[].file.path and multiple entities so all referenced files are staged as Nextflow path() inputs. Referenced config YAMLs (.yaml/.yml in entities[].file.path, eg for nanobody scaffolds) and the PDB/CIF files they reference internally are collected and staged so BoltzGen’s per-generation random selection over those configs is preserved.
  • Versioned documentation using mike; docs are now deployed for main (alias: latest), develop (alias: dev), and version tags.

Fixed

  • Boltz refold RMSD and ipSAE: BOLTZ_COMPARE_COMPLEX and BOLTZ_COMPARE_BINDER_MONOMER now use Boltz complex chain A = binder and B = target (from create_boltz_yaml.py IDs), while the input design keeps ${binder_chain} / ${target_chain}. Previously the same chain letters were used on both structures, which mis-superposed RFD3-style complexes (target A, binder B) and inflated rmsd_target_aligned_binder / ruined aligned PDBs; ipsae.py now receives --binder-chain A --target-chain B for Boltz outputs.
  • Boltz: BOLTZ, BOLTZ_COMPARE_COMPLEX, and BOLTZ_COMPARE_BINDER_MONOMER tee boltz predict to .boltz_predict_console.log and exit 1 if the log contains ran out of memory, skipping batch (Boltz may otherwise exit 0 and leave outputs missing).

Changed

  • merge_scores.py: drop from the right any column that exists in the current left before each merge so the result has no _x/_y suffixes; treat .cif as path-like (use basename for merge key) in addition to .pdb.
  • trim_to_contigs.py: parse_contigs() now supports RFD3 v3 contig format (comma-separated, /0 as separate element, e.g. A18-132,/0,65-120) in addition to v1 style.
  • Major project restructure shifting individual workflows into workflows/, each launched via a single main.nf entry point with the --method flag.
  • --method rfd for RFdiffusion binder design (previously main.nf)
  • --method rfd_partial for partial diffusion (previously partial.nf)
  • --method bindcraft for BindCraft (previously bindcraft.nf)
  • --method boltzgen for BoltzGen (previously boltzgen.nf)
  • --method boltz_pulldown for Boltz Pulldown (previously boltz_pulldown.nf)
  • Modules reorganised into modules/local/ with workflow-specific subdirectories (rfd/, bindcraft/, boltzgen/, common/).
  • Extracted common Boltz-2 refolding and scoring logic into BOLTZ_REFOLD_SCORING subworkflow (subworkflows/local/boltz_refold_scoring.nf).

Fixed

  • BindCraft (workflows/bindcraft.nf): omitting --hotspot_res no longer fails in validateHotspotRes with Unknown method invocation 'trim' on Boolean type.
  • BindCraft (workflows/bindcraft.nf): allow explicit --hotspot_res="" to pass through as a no-hotspot BindCraft setting, and normalise empty hotspot list entries before writing settings.
  • Declare bindcraft_batch_size default in nextflow.config so Nextflow does not warn when parsing modules/local/bindcraft/bindcraft.nf (unrelated to -profile m3).
  • rmsd4all.py: cap worker processes to the number of pairs so single-pair comparisons (e.g. RFD3_RMSD with one design vs one refold) no longer spawn a large Pool and appear to hang; sequential path is used for one pair with progress logged.
  • rmsd4all.py: add --max-structural-iterations (default 100). Biotite's refinement loop uses max_iterations=inf by default and only stops when anchors stabilize; with 3di the anchor set can fail to converge (oscillate) so the loop never exits. Capping iterations fixes the hang; 0 = no limit.
